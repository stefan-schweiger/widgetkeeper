# Web dashboards

- Our widgets (and other apps', below) in any browser on the home network, on dashboards laid out on the page itself (the user's choice over reusing Homey dashboards; home network only; a personal API key per browser). `settings/dashboard.html` (+ `dashboard.js`, `dashboard.css`, `socket.io.js`), served by the Homey without login at `http://<ip>/app/<appId>/settings/dashboard.html`. The app settings page shows the address (`GET /web/address`, `homey.cloud.getLocalAddress()`). It loads the kit as `../widgets/spacer/kit.js` (and `.css`), the Homey's path, not the repo's `public/` one (a 404 on the Homey, which left `WidgetkeeperKit` undefined and the value slots empty, 2026-10-18); the dev pages load their own. `lib/WebDashboardService.ts` keeps the dashboards.
- Each widget runs **unchanged** in an iframe of its own `../widgets/<id>/index.html?widgetInstanceId=web-<dashboardId>-<widgetId>`: the Homey injects its SDK (`/js/crossframe.js`, `/widgets/js/homey.widgets.js`) and stylesheet (`/widgets/css/homey.widgets.css`, which the page loads too: Homey's real tokens, fonts and `.homey-dark-mode`) into every served widget `index.html`. Outside a WebView the SDK's crossframe posts to `window.parent`, so the page answers it as Homey's dashboard does: `getInitialData` (`{settings, deviceIds, transparent, locales, language, devmode, fontScale, isDarkMode}`), `api` (→ `POST /web/call {type, method, path, query, body}` → the widget's own `api.ts`, `callWidgetRoute()`), `registerRealtimeListener` (data is the event name; every event is a `cb` with `args: [data]` and that callbackId), `ready`/`setHeight` (the iframe's height), `popup`, `shortPressHapticFeedback`, `emit`. Messages are `CF2_MESSAGE` + UTF-16 hex JSON (`hexEncode()` through a byte table); an error is `{type: 'Error', data: message}`. The iframes are `loading="lazy"`.
- A widget of ours that `popup()`s `#/d/<id>` (on the page's own path, or the frame's) opens that dashboard in place (`dashboardLink()`), not from the editor; any other URL opens a window. Dashboard Shortcuts (`.claude/rules/widgets/shortcuts.md`), a widget only the web dashboards offer (deprecated in its manifest, so Homey's own Add widget leaves it out), is what uses it.
- Requests: `fetch('/api/app/<appId>/…', {Authorization: 'Bearer <key>'})`, same origin (a personal API key may call the app's API, 2026-10-10). The key is `localStorage` `widgetkeeper.web.key`; a 401/403 forgets it, stops the socket and brings the key screen back. The app's own token still does everything else. A route that acts with the stored key (`routeKeyUse()`: variables `/set`, flows `/trigger`, media `/button` (a `card:` needs `homey.flow`), stack `/pages`, lights `/mood`, and a stack `/call` of those) only runs when the page's own key may do the same: `/web/call` carries `key`, and `PersonalApiKey.scopesOf()` reads its scopes (remembered 60 s; a passing failure throws and isn't kept). `/web/autocomplete` carries it too, for the Smart Stack's dashboards (`autocompleteKeyUse()`); else `{ok: false, reason: keyScope | keyInvalid}`, so a weaker key can't borrow the stored one's permissions.
- Realtime without homey-api: socket.io v2 to the Homey (`transports: ['websocket']`), `emit('handshakeClient', {token, homeyId}, cb)` → `{namespace: '/api'}`, `io.socket(namespace)` and `.open()`, `emit('subscribe', 'homey:app:<appId>', cb)`, then events arrive as `ns.on('homey:app:<appId>', (event, data))` (2026-10-10). `homeyId` comes from `/web/setup` (`homey.cloud.getHomeyId()`). Any failure or disconnect starts over (2 s, doubling to 60 s); after an outage over 30 s the frames reload. `No live updates` shows while it's down.
- Endpoints (`api.ts`): `GET /web/setup` (`{appId, homeyId, language, strings, widgets: widgetTypes(), dashboards, front, maxDashboards}`), `GET /web/devices?type=&query=` (the manifest's `devices.filter`: `class`/`capabilities` as `a|b`, the class or the virtual class; `{id, name, zone: {id, name, path} | null, icon}`, the icon the same-origin `/api/icon/<id>` (no login needed) or the library URL), `GET /web/values?type=`, `POST /web/autocomplete {type, setting, query, settings}`, `PUT /web/dashboards` (a new one gets an id), `PUT /web/front` (the front page's order and carousel), `DELETE /web/dashboards/:id`, `POST /web/dashboards/:id/copy` (Duplicate), `GET/PUT /web/backup` (the front page's backup), `POST /web/call`, `GET /web/address`, and the password routes.
- On/off: the app setting `webDashboardsEnabled` (off unless `true`), a checkbox on the settings page, which shows the address only while it's on. Off, `/web/setup` answers only `{disabled: true, language, strings}` (`web.off`) and every other `/web/…` route but `/web/address` throws `Web dashboards are turned off` (`assertEnabled()`); the dashboards stay. The page's `failed()` goes back to `start()` on that error.
- **Remote access** (the user's request, 2026-10-21; 1.0.2): Homey's cloud relay `https://<homeyId>.connect.athom.com` (what my.homey.app and homey-api's `cloud` strategy use) serves the page, the widgets' `index.html` with the SDK injected and `/widgets/js/homey.widgets.js` without login (200), relays `/api/app/…` to the Homey (no key: 401 `Missing Session` from `homey-local`) and upgrades the socket (`/socket.io/?EIO=3&transport=websocket`: 101); all checked with curl 2026-10-21. The page builds every URL from `location.origin`, so it runs there unchanged. Not inside my.homey.app: its settings frame is sandboxed without same-origin, so `localStorage` throws. `GET /web/address` answers `{url, remoteUrl}` (the latter from `homey.cloud.getHomeyId()`; the SDK has no getter for it). The app setting `webRemoteAccess` (**Remote access**, a checkbox under the address, off unless `true`; the away address shows only while on) gates it, but **Homey doesn't tell a route which address a request came in on**, so the page says so itself: on a `*.connect.athom.com` host (`AWAY`) `request()` adds `away=1`, and `assertEnabled(away)` throws `Web dashboards are turned off away from home` (the page's `/turned off/` handling), `/web/setup` answers `{disabled: true, away: true}` (`web.offAway`). A key holder who leaves `away` out gets through, as they could reach Homey's own API through the relay anyway: the key is what guards it. Diagnostics' `web.remote`.

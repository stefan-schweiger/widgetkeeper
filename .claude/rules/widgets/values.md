# Device Values widget (`values`)

- Quick Actions' tiles, 3 or 2 per row (`columns`, `"3"`; `data-columns`), each one capability value: the capability icon (20 px, `left center`) and the value (right, ellipsized) over the device name; no device icon (the user's choice). Display only. `lib/ValueService.ts`; transparent.
- Slots `slot1`…`slot6`: autocompletes (`listSlots()`), `None` first (id `none`: an empty tile; the widget skips ids without a colon), then every device × capability as `Device · Title` (described by zone and units), id `<deviceId>:<capabilityId>` (`parseSlot()` splits on the first colon). A pair may fill several tiles; tiles are keyed by slot and position. The tiles are named with Rename tiles (`tile-names.md`); the `nameN` settings (`  – Name`, shipped in 0.9.0) were removed in 1.0.0, with no carry-over (the user's choice, 2026-10-18). The usual device widget's tracking, per slot.
- Second values (`second1`…`second6`, `  – Second value` under each `Tile N: value`, the head's titles given `: value` for the grouping; the user's pick of three layouts mocked up in `temp/values-two-values-mockup.html`, 2026-10-18: "In the corner", over a two-column wide tile and a taller two-line tile): autocompletes (`listSecondValues(settings.slotN.id, query, n)`) of the other `valueCaps()` of Tile N's device, by capability title (units as the description), id `<deviceId>:<capabilityId>`, `None` first; without a device in Tile N only `None`, described `values.pickTileFirst`. A setting can't clear another, so `mount.js` drops a second value of another device (Tile N changed since) or the slot's own, and sends `&seconds=<capabilityId>,,…` in the slots' order (left out when none). The service tracks it as a slot of its own and adds `second: {capabilityId, capability, value}` to the entry; one it can't read is left out. Shown as text only, small and muted at the end of the name's row (`.vt-row`, `.vt-second`: 14 regular, the 14 px glyph or icon, 3 px gap; in pill tiles the value's row, 8 px after it), hidden while renaming. The first value leads: colour, fill, the On tint, the name and the tile key. The name is cut first; in pill tiles the second value (`.has-second` makes the value as wide as its text only then, so tiles without one are byte-identical to before). In the `.vt-ink` copy too. Realtime `values:state` updates it by capability.
- Shown capabilities (`valueCaps()`): `number`, `boolean`, `enum` and `string` with `getable !== false`.
- The kit's `formatValue()` (also `window.formatCapabilityValue`; Sparklines, Charts and the web value picker use the same): numbers in the device locale to `decimals` (else at most 1), with the units (no space before `°…` and `%`); booleans `On`/`Off`; enums by their value title; `null` → `–`. A `true` boolean gets Quick Actions' blue tint.
- Percentage fill (`percentFill`, off; `redBelow` 10, `yellowBelow` 20): a `%` number (`percentOf()`) fills the tile from the left to its value (`.filled`, `--vt-fill`, a hard-stop gradient), red/yellow/green (`levelOf()`) mixed 22 % into the tile (`--vt-fill-mix`; 45 % until a user asked it to match the Flow colours). `dim` is `%` with `min: 0, max: 1` (2026-10-05), so a 0–1 `%` range is scaled to 0–100, text too (the service sends `min`/`max`).
- Icon: the capability's own `iconObj` (`fetchSvgIcon()`), else a built-in glyph by base id (thermometer, drop, bolt, sun, cloud, battery, bell for `alarm_*`, power, padlock, bulb for `dim`, wave, gauge as the fallback). `measure_battery`/`alarm_battery` always get the battery glyph (`iconFor()`, also in Sparklines; wk-029: some drivers ship a battery with a fixed fill). Homey's standard capability icons aren't public (`my.homey.app/img/capabilities/…` doesn't exist).
- Tile colour from a Flow (a user's request: a fridge blue below 5 °C and red above, internet checks green/red): the app's action card `values_set_color` ("Set the tile colour of [[slot]] to [[color]]"; `slot` autocompletes `listColorSlots()`, `listSlots()` without `None`; `color` is `default` (reset), `red`, `orange`, `yellow`, `green`, `blue` or `purple`). A Flow can't address a widget instance, so the colour belongs to the device value: every tile showing it, in any Device Values widget. `setColor()` keeps it in the app setting `valueColors` (`{'<deviceId>:<capabilityId>': colour}`) and sends `values:color {deviceId, capabilityId, color | null}`; `/state` entries carry `color` when one is set. `data-color` mixes it 22 % into the tile with the icon in the text colour, wins over `.active`, and with `percentFill` colours the fill instead of its level. Orange and blue are Homey's tokens, purple `#9033FC`, yellow `#F5C518` (no token).
- `colorStyle` ("Colour style", after `tileStyle`; CLAUDE.md *Widget styling*): `soft` ("Muted"; a missing or unknown value too) or `deep` (`.wk-deep`), which replaced Bright (wk-051, never released; a stored `bright` reads as Vivid). A user found the soft yellow mustard and the orange brown (`#493F1E`, `#482E20` on the dark tile), which no hex can fix at a 22 % tint. Vivid sets `--vt-fill-mix: 100%` with the palette's shades and the text and icon in `--vt-ink` (white; dark on yellow); an On boolean is the blue shade, solid. A fill ends partway, so each tile has `.vt-ink` (made only in Vivid, `aria-hidden`): the icon, value and name again, laid out as the tile, in the ink colour and clipped to `--vt-fill` (`clip-path: inset()`). Not while renaming (`:not(.renaming)`), so the field stays readable. Bright's dark text on Homey's real red was only 3.4:1 (`#D81C1D`; the 5.1:1 measured on the fallback), one reason Vivid uses white.
- `tileStyle` ("Tile style", after `columns`): `compact` (the default; a missing or unknown value too) or `pill` (`.vt-pill`, the user's request, 2026-10-18): Sensor Alarms' tile (52 px, the 24 px muted icon beside the name in 14 bold over the value in 14 muted, 18 px lines, `#2B2C36` in dark mode, no rim). `parts()` builds the tile and its `.vt-ink` copy in either layout, so `render()` doesn't know the style. It follows `columns` (the user's choice over always 2, though at 3 on a 300 px widget the text is cut short). Every colour rule applies unchanged; in Vivid the muted value turns to ink with the text.
- `GET /state?slots=a:cap,b:cap[&seconds=cap2,]`: per valid slot `{deviceId, capabilityId, name, capability: {title, type, units, decimals, values, icon}, value, second?}` or `{deviceId, capabilityId, missing: true}`. Realtime `values:state`.

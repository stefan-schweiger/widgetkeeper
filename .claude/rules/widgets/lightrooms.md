# Lights by Room widget (`lightrooms`)

- For many lights in many rooms (the user's brief, 2026-10-23): control each room and each light. Chosen from eight mockups (direction C, "one long list", `temp/lights-rooms-directions.html`), then refined by the user: rooms closed by default, a tap on the name opens one, the room icon before the name, the chevron after the state, Moods and the swatches inside. The user picked the device picker over every light in the house (a light that isn't picked isn't shown; no "choose lights" mode). Built on Light Controls: read `lights.md` too; the service, the bar, the chip, the swatches, the Moods and the colour maths are its.
- Back end: `app.lights` (`lib/LightService.ts`), so tracking, `lights:state`, group devices, Moods and the API key are Light Controls'. `api.ts`: `GET /state?deviceIds=` → `{lights, zoneIcons}` (`getState()`'s entries, and `zoneIcons(zoneIds)`: each room's zone icon as an SVG data URL), `POST /set`, `GET /moods?zones=`, `POST /mood` (`keyResult()`; `routeKeyUse()` has `lightrooms POST /mood`). In `WEB_APIS` (`api.ts`), not a Smart Stack page (not in `STACK_TYPES`: a tall list of rooms suits a slide badly; can be added later).
- Room icons are **Homey's own**: the zone's `icon` id (`kitchen`, `livingRoom`, `bedroomKids` … and aliases like `living`, `bed`, `stairs-down`) → `https://my.homey.app/img/zones/<file>.svg` (`zoneIconUrl()` in `lib/deviceIcon.ts`, the mapping read from the web app's `getIconForZone()`, 2026-10-23; unknown ids get `zone.svg`), fetched once per URL by the app like library device icons (`fetchZoneIcon()`, `cachedSvg()`). A room without one (a failed fetch, the Other room) gets the rounded-square fallback. The dev page and the preview frame use drawn stand-ins (renders must not need the network).
- Front end (`createLightRoomsWidget`, `--lr-*`, `lr-` classes): rooms in the order of their first picked light; lights without a known zone and missing ones in a last room, Other. A card: icon, name (14 bold), the state (12/16 muted: Off, All on, `2 of 3 on · 55%`, without the percentage when no light dims; `lightrooms.level` puts the space before % per language), the chevron (right, down when open), the switch (40 × 24 in a 60 × 44 hit area; on while any light is; all off when any is on, else all on, one `/set` per light) and the room bar (average brightness of the lights that are on, sets every light; 0 is off; hidden when no light dims). Lit, the card is tinted at the top with the lit lights' colours (at most 4), fading into the tile by 96 px.
- A tap on the header (not the switch) opens or closes the room; several can be open; the open set lives in memory per screen, so a refresh keeps it and a reload starts closed (`opts.open`, zone ids, is only for the dev page and renders). Open: the room's Moods (`showMoods`, on) as Light Controls' pills in one row that scrolls sideways, then a row per light (40 px): the chip, the name, a slim bar (On/Off text for a light without `dim`). A tap on the row toggles the light; the chip (hue glyph, thermometer for whites only, a pie for a Homey group in several colours) opens the swatches **under the row** (Light Controls' 7 colours then 5 whites, one white for colour without temperature, ✕ last; closes on a pick, ✕, the chip, 8 s, or closing the room). A light with neither has a plain dot whose tap toggles it. A swatch sets one light in Light Controls' order (`onoff`, `light_mode`, then hue + saturation or temperature).
- Copies kept equal by `test/widget-html.test.ts`: `onTap()` and `wireBar()` with Light Controls and Curtains. Light Controls' colours, palettes, chip glyphs and `moodDot()` are in the kit (`WidgetkeeperKit.lights`; the glyphs are built on first use, so loading the kit needs no `btoa`).
- Settings: `devices` (Light Controls' filter), `showMoods`, `palette` (Default, Warm, Dusk; no Room's Moods, since Moods have their own row), `barMin`, `colorStyle` (Vivid: a stronger top tint, 40 % light and 48 % dark against 22 and 26).

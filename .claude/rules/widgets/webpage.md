# Web Page widget (`webpage`)

- A page the user picks, in an iframe (wk-081, forum #240: a Buienradar rain radar with country/province/region/city buttons that fills the widget and doesn't open the site on a tap). The user chose a general widget over a Buienradar one (2026-10-22): Buienradar's free-use page (buienradar.nl/overbuienradar/gratis-weerdata) allows its gadgets on your own website or intranet, but "mobile applications or commercial purposes" need its permission, and its tiles and radar images (`tiles.buienradar.nl`, `image-lite.buienradar.nl/3.0/metadata/RadarMapRain…`) aren't offered for reuse. So the app names no site, and the user asked (2026-10-22) for no rain radar or Buienradar in any wording users see (manifest, strings, store text, README, changelog); the README only says the user follows the site's terms. `scripts/test-dashboards.mjs` still uses the gadget's address, as "Map gadget". `homey-widget-full`, not transparent, default height 320.
- **Why the gadget had borders:** it's a Leaflet map in a fixed box on a white page (`zoommap.min.css`: `size=1` 120×200, `2` 256×256, `2b` 330×330, anything else 550×512), so a wider frame shows white beside it and a shorter one cuts the bottom off. The whole box is an `<a target="_blank">`. Its generated address has no region (the generator's Europa option isn't in it), so the rain is always the NL/BE radar image, even where the map shows elsewhere in Europe.
- Settings: `url` ("Address"; `https://` added without a scheme; anything but http(s) is refused, `webPageAddress()`), `pageWidth` (0–4000, default 0: drawn at the widget's own width, unscaled), `pageHeight` (20–4000, default 320), `interactive` ("Let the page be tapped", off), `refresh` (minutes, 0 never, ≤ 1440), then `Button 1: name` / `  – Address` … 4 (`b1Name`, `b1Url` …). Numbers are rounded and clamped; anything else is the default.
- Scaling (`webPageBox()`): the iframe is `pageWidth × pageHeight` px with `transform: scale(widgetWidth / pageWidth)` from the top left, in `.wp-page`, which clips it at `floor(pageHeight × scale)`, so the page always covers the box. A `ResizeObserver` on the root re-lays it out and sends the height.
- `sandbox="allow-scripts allow-same-origin allow-forms"`, no popups or top navigation, so links never open (Chromium logs "Blocked opening … allow-popups"), and `referrerpolicy="no-referrer"` (the Homey's address isn't sent). `allow-same-origin` is for the page's own storage and cookies; a page on the widget's own origin (one the Homey serves) could undo the sandbox, which only the user's own Homey pages are. Not `interactive`: `.wp-shield` over the page takes the taps, and a drag scrolls the dashboard.
- Buttons: shown with two or more that have an address (a name defaults to `Button N`). The widget always opens on `url`; the button whose address is the shown one is lit (`.active`, a raised neutral segment: no state colour, so no Colour style). Thermostat Presets' segmented row (`presets.css`) one line high (44 px), copied in `widget.css`. `onTap()` is Flow Buttons' copy.
- A switch or a reload (`refresh`, only while visible; one due while hidden runs on `visibilitychange`) loads the new page in a second iframe behind the shown one and drops the old one on its `load`, or after 20 s anyway, so a wall tablet doesn't flash blank.
- `{lat}`/`{lon}` in any address: `mount.js` asks `GET /location` (`pageLocation()`: `homey.geolocation`, 2 decimals, `{noLocation: true}` at 0, 0) and the widget waits for `setLocation()`; without one it says so. Ready isn't held for the page's own loading. No other requests, no realtime, no diagnostics.
- Not a Smart Stack page (its frame would take the stack's swipes): not in `STACK_TYPES`, `TYPES` or `stack_show`. On web dashboards it nests an iframe in the widget's frame; an `http://` page on the HTTPS away address is blocked as mixed content.
- `dev/webpage-preview.html` shows `dev/webpage-sample.html`, a neutral 550 × 512 wireframe page that is one big `target="_blank"` link like the gadget (`?zoom=6|8|11|13` names the view in its footer); the preview images show the same kind of wireframe (the user wanted no map or rain in them, 2026-10-22). Checked in the desktop app's browser pane (2026-10-22): no borders at 300, 358 and 620 px, the buttons switch, the shield and the sandbox block the link. The tests run with happy-dom's `disableIframePageLoading`, so no page is fetched.
- Not yet tried: an iframe inside a widget in Homey's phone apps (iOS and Android WebViews), Buienradar's real gadget scaled on a phone and a tablet, and whether Homey's widget frame allows framing other sites at all.

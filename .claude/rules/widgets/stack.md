# Smart Stack widget (`stack`)

- Our widgets from another dashboard, one at a time (the user's idea: an iOS-style Smart Stack). The user sets up a dashboard of the widgets to rotate and picks it in the `dashboard` autocomplete. `lib/StackService.ts`; `widgets/stack/`. Transparent.
- Dashboards (2026-10-10): `dashboards.getDashboards()` → `{id, name, columns: [{id, widgets: [{id, title, titleHidden, type, data}]}]}`. Ours are `type: 'app_webview'` with `data.appWidgetId: 'homey:app:<appId>:<widget>'`, `data.settings` (autocompletes as `{id, name, description}`) and `data.deviceIds`; native widgets (`light_group`, `sensors_selection`, `device_camera_live` …) can't be rebuilt. `dashboardPages()` keeps ours in `STACK_TYPES` (not `stack`, `spacer`, `dayssince` or the web-only `shortcuts`), column by column. The read needs `homey.dashboard.readonly`, so it goes through the personal API key; cached 60 s (5 s for the autocomplete).
- Homey serves every widget's files at `/app/<appId>/widgets/<id>/<file>` without auth, so the stack frame loads a page's `../<type>/widget.css`, `widget.js` and `mount.js` (once per type; skipped when the mount is already there, as in the preview and tests). The frame CSS (`.homey-dark-mode .tw-frame` …) works on a slide.
- Each page gets a stand-in Homey (`pageHomey()`): `api(method, path, body)` → `POST /call {type, method, path, query, body}` (without `perf=`), which `widgets/stack/api.ts` hands to that widget's own `api.ts` (`PAGE_APIS`, a static import of all 23; only the routes in the manifest's `widgets.<type>.api`); `on`/`__` are the stack's (realtime is app-wide); `getSettings`/`getDeviceIds` come from the page; `getWidgetInstanceId` is the dashboard widget's id, so a Timers page shares the original's timer and a Media page its speaker choice; `setHeight`/`ready` re-measure.
- Layout: a native horizontal scroll-snap track of full-width slides (`.sk-slide` with the widget's `frameClass`; a non-transparent widget's slide gets `.sk-card`, Homey's background and a 10 px radius), and dots (the current one a pill, one that wants attention blue). `dotsPosition` (`below`/`above`) and `dotsSize` (`small`/`large`), both the user's asks, sit under `showDots`. The widget's height follows the current slide (the user chose that over a fixed height). A slide's mount may return `setVisible(v)` (Cameras stops snapshots off screen, the Electricity Overview and Charts their redraws).
- Rotation (`createStackWidget`, `tick()` every second, nothing while `document.hidden`): every `interval` (10 s … 5 min or `never`, default 30 s). A swipe, a dot or any `pointerdown` on a page holds it for `resumeAfter` (60 s). Priority: a Flow request (until it runs out, even during a hold; the newest first, and one just made comes forward even while an earlier one's page shows), then pages that want attention (`smart`, on: one that starts takes the screen, several take turns every interval; one the user moved away from (`dismissed`) only comes back when it starts again), then plain rotation. Nothing moves on its own during a hold (`pickNow()`) except a Flow request (`request()`, or a refresh's `setRequests()` bringing a new type). Expired requests repaint their dot from `tick()`. The swipe guard (`programmatic`) uses `Date.now()`, not `opts.now`, so a fixed clock doesn't block swipes.
- Attention (`stackAttention()`, `createStackAttentionWatcher()`): media while `speaker_playing` (the speaker this screen switched to, from the media widget's `localStorage` key, else the default); timers while the instance has a timer; cameras on `alarm_person/vehicle/pet/motion` (through Sensor Alarms' `/state`); sensor alarms on a counted alarm (the page's `includeStates`); locks on anything not secure. A page's own `/state` answers feed it (`seen()`); `refresh(freshMs)` reads the rest through `/call` 3 s after mounting and every 5 min, skipping a page seen in the last minute; then `media:state`, `timers:state`, `sensoralarms:state` and `locks:state`.
- Loading: every page type's files are added at once (scripts with `async: false` run in the order added: deps, `widget.js`, `mount.js`). The page on screen mounts first, the others once it's `ready` (or 2 s on, `OTHERS_AFTER_MS`); a page brought on screen before then mounts at once (`mountSlide()`, once per page).
- Flow cards: `stack_show` ("Bring [[widget]] forward on Smart Stacks for [[minutes]] minutes"; a dropdown of the 23 widget names) and `stack_resume`; a Flow can't address one stack, so they apply to every stack page of that type. Realtime `stack:show {type, until, now}` / `stack:resume`; the service keeps the requests, so a stack that loads later gets them in `/pages`. `until` is the Homey's clock: `toLocal()` moves it into the screen's by the difference of the two `now`s.
- `GET /pages?dashboardId=` (`{ok: true, pages, requests, language}`, `missing: true` for a deleted dashboard, or `{ok: false, reason}`) and `POST /call`. The widget re-reads `/pages` every 5 min and reloads the frame when the pages or their settings changed, or when the dashboard is gone or empty after pages were mounted. `Homey.ready` waits (≤ 3 s, `wireFrame()`'s `maxMs`) for the page on screen to call its `ready` (`readyPages`). Without a usable key the `dashboard` autocomplete lists one item, id `none` (`stack.<reason>` over `stack.keyHint`), treated as no dashboard. Diagnostics' `stack`: reads, the last error, the running requests, and `dashboards` (a trial read through the key: a count, the key problem, or `timeout` after 5 s; 6 on the test Homey, 2026-10-10).
- Not yet tried on the Homey or the phones: that a page's files load from `../<type>/` in the phone apps, that Android's dashboard doesn't take the swipe (the dots are the fallback), and the memory use with many pages.

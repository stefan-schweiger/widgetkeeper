# Renders (app images, previews, screenshots, clips, showcases)

- Renders run headless Edge through `scripts/headless.mjs` (`EDGE`, `HEADLESS`, `freshProfile()`, `edge(args, {virtualTime})`: default `--virtual-time-budget=4000`, `null` for none; the icon download). They show made-up data on a fixed clock: **never put real device names or readings in them.** Every render is byte-identical between runs, except the live electricity chart's antialiasing (the electricity screenshot and the Home, Energy and Kitchen showcases).
- `npm run app-images` (wk-067): the three App Store PNGs (`assets/images/`, 250×175, 500×350, 1000×700) from the widget previews, with sharp, no Edge (`scripts/app-images.mjs`). `dev/app-images.json` sets the widgets and their order (`columns`), the previews' `theme`, `tilt`, `columnWidth` (a fraction of the image), `gap`/`stagger` (preview px) and the background: a gradient in the brand colour `#2A1958` (`stops`, evenly spaced, at a CSS-like `angle`) with a soft radial `glow` (centre and radius as fractions), drawn as an SVG by sharp. It replaced a blurred photo (`dev/hero.webp`) at the user's request (2026-10-18). Each card is cut to its opaque box (alpha ≥ 250, not `trim()`, which takes the shadow) plus 64 px of shadow and scaled to 800 px wide (≤ 1), the columns are centred and staggered, the layer rotated at full size, then scaled down once per size; it throws rather than scale a preview up. Same inputs, same bytes. `npm run previews` re-renders them when it rendered a preview they use. `test/app-images.test.ts` checks the config and the sizes.
- `npm run previews [-- qa-dark …]`: the widget preview PNGs from `dev/widget-previews.html` (the "Widget Previews" Claude Design project; `?p=elec-dark` shows one frame), plus the README's `docs/previews/<widget>-<light|dark>.png` (cropped to the card with sharp). A new widget needs an entry in the frame-id prefix → widget map in `scripts/render-previews.mjs`. The README overview isn't a table (GitHub's `max-width: 100%` collapsed the image column on phones): each widget is one `<p>` with a 120 px `<picture>` floated left (`align="left"`), the bold linked name, the description and `<br clear="left">`.
- `npm run screenshots [-- thermostat …]`: `docs/screenshots/*.png` from the `<section class="shot">` ids of `dev/screenshots.html`: the real widgets in Homey's dark mode, 358 px (a phone's widget width) at 3x, no title, transparent. The data is the showcase's house; `dev/mock-dashboard.js` picks widgets (`findWidget(type, n)`) and mounts them through `MOUNT` (`dev/showcase-mount.js`). It downloads the library icons into `temp/screenshot-icons.js`.
- `npm run clips [-- lights stack]`: the README clips `docs/clips/<id>.webp` (`lights`, `stack`, `media`, `timers`, `sensordots`, `curtains`, `rename`; animated WebP plays inline on GitHub, an MP4 would be a link); they replaced the Light Controls, Activity Dots, Timers, Curtains and Media screenshots. `scripts/render-clips.mjs` drives `dev/clips.html?c=<id>` over DevTools (`--remote-debugging-port`, Node's `WebSocket`) with real touch events (`Input.dispatchTouchEvent`), screenshots as fast as they come (~16/s) and joins them with sharp 0.34+ (`join: {animated: true}`). The page has simulated devices (the clock runs on), a drawn finger and a callout on top of the widget (the user's choice; keep its text under ~40 characters).
  - A clip is steps in `CLIPS`: `say` (with `icon`), `wait`, `tap`/`drag` (a selector, the match's index `i`, points as fractions of its box), `type` (`Input.insertText` a key at a time, then Enter), `run` (a control on `window.clip`, e.g. `doorbell`), `probe` (prints a page value). It may return `width` (the stack: a backdrop so its large dots read on GitHub's light page) or `grow` (Media: recorded tall, cropped with `sharp().trim()`).
  - Rendered at 1x (touch moves 1:1), screenshots at 2x (`clip.scale`). Headless Edge scrolls a native scroller only half as far as dispatched touch moves (2026-10-10), so the stack's swipe runs on past the edge; `Input.synthesizeScrollGesture` didn't scroll at all.
- `npm run showcase [-- home energy …]`: `docs/showcase/<id>.png` from `dev/showcase.html?d=<id>`: three columns of real widgets on Homey's dark dashboard on a drawn 16:10 tablet (1280 × 800), 2x. The README's top image is `home.png`, its Dashboard examples all seven. The data is a made-up house, "Solbakken", on Tuesday 6 October 2026 at 18:40 (`dev/showcase-data.js`; `dev/fixed-clock.js` replaces `Date`, for the screenshots and clips too). A dashboard is `SHOWCASE[id] = {title, colorStyle?, columns: [[{type, …}]]}`; `MOUNT` creates each type, and `colorStyle: 'deep'` gives every widget Vivid (Security and Climate, 2026-10-19; the entries stay as they are, so `findWidget()` users keep Muted), and `theme: 'light'` light mode (Garden, the user's ask: `light-mode` in place of `homey-dark-mode` on html, Homey's light dashboard `#F4F4FA`, white cards and the light tokens). Climate has Room Health, Value Matrix and Variable Presets, Energy an overlaid Charts, the Kitchen Days Since; the README screenshots take Room Health and Value Matrix from there. `findWidget(type, n)` counts in dashboard order, so adding or removing a widget of a type before another page's `n` changes that page. The script warns when a column runs off the screen. The cameras show `dev/cameras/<id>.webp` (AI-generated snapshots of the made-up house); the dev previews keep the drawn scenes of `dev/mock-cameras.js`.
- `npm run web-showcase [-- dashboard front editor]`: `docs/web/<view>.png` from `dev/web-showcase.html?v=<view>[&d=<id>]`: the real `settings/dashboard.js` in a drawn desktop browser with the showcase's dashboards, the widgets mounted in place of the iframes (`mountWebDashboards(root, {mountWidget})`; only the dev page passes it). Each dashboard has a backdrop (`BACKGROUND`), and web Home's first column has Dashboard Shortcuts in place of the heat pump. The `light` view is the Kitchen (`LIGHT_BOARD`, a light dashboard on Sand; the front page's miniatures follow the page's theme, so its card stays dark) in a light browser. The page fetches `/app.json` and the locales, which `file://` can't, so the script serves the repo root from a child process (`edge()` blocks).
- `npm run forum-images`: `docs/forum/<showcase|web>-<id>.jpg` for the Homey Community post: the transparent showcase and web PNGs on the App Store images' brand background (`background()` from `scripts/app-images.mjs`), 1380 px wide (2x the post's 690), JPEG 88. Discourse turns a large transparent PNG into a JPEG on white, which showed the first post's tablet in a white box (2026-10-19). Run it after `showcase` and `web-showcase`.
- `npm run whats-new`: the 1.0.0 poster `docs/whats-new-1.0.0.png` from `dev/whats-new.html` (needs `docs/web/settings.png`). Opaque, so it goes in the forum as it is.
